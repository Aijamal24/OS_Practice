# Практическая работа №2 — Вариант B

## 1. Цель работы

Разработать Bash-скрипт для анализа лог-файлов по уровням `ERROR` и `WARN`, добавить режим ограничения количества результатов `--top N`, реализовать проверку аргументов и существования каталога.

Также написать программу на Python, которая получает путь к файлу через аргумент командной строки и выводит его размер в байтах.

С помощью `strace` исследовать системные вызовы при запуске Python-программы и команды `cat`, а также сравнить количество системных вызовов.

## 3. Входные данные

Для проверки скрипта были созданы два лог-файла:

```text
data/01.log
```

Файл `data/01.log` содержит сообщения модулей `auth`, `database` и `api` с уровнями `ERROR` и `WARN`.

## 4. Скрипт report.sh

### Назначение

Скрипт принимает:

```text
./report.sh <каталог> <ERROR|WARN> [--top N]
```

Скрипт:

* проверяет наличие необходимых аргументов;
* проверяет существование каталога;
* принимает только уровни `ERROR` и `WARN`;
* подсчитывает количество сообщений каждого модуля;
* сортирует результат по количеству сообщений по убыванию;
* поддерживает ограничение количества результатов через `--top N`;
* возвращает код `1` при ошибке аргументов или каталога.

### Запуск

Перед запуском скрипт был сделан исполняемым:

```bash
chmod +x report.sh
```

### Проверка ERROR

Команда:

```bash
./report.sh data ERROR
```

Результат:

```text
module | count
--------------
api 3
auth 3
database 2
```

### Проверка WARN

Команда:

```bash
./report.sh data WARN
```

Результат:

```text
module | count
--------------
auth 2
database 2
api 1
```

### Проверка --top

Команда:

```bash
./report.sh data ERROR --top 2
```

Результат:

```text
module | count
--------------
api 3
auth 3
```

Таким образом, режим `--top 2` оставляет только два первых результата после сортировки.

## 5. Проверка ошибок

### Отсутствуют аргументы

Команда:

```bash
./report.sh; echo $?
```

Результат:

```text
Usage: ./report.sh <каталог> <ERROR|WARN> [--top N]
1
```

Код возврата равен `1`, как требуется в условии.

### Несуществующий каталог

Команда:

```bash
./report.sh /nope ERROR; echo $?
```

Результат:

```text
Ошибка: каталог '/nope' не существует.
Usage: ./report.sh <каталог> <ERROR|WARN> [--top N]
1
```

### N не является числом

Команда:

```bash
./report.sh data ERROR --top abc; echo $?
```

Результат:

```text
Ошибка: N должно быть числом.
Usage: ./report.sh <каталог> <ERROR|WARN> [--top N]
1
```

Во всех проверенных ошибочных случаях программа возвращает код `1`.

## 6. Программа hello.py

Файл `hello.py` получает путь к файлу через аргумент командной строки, открывает файл в бинарном режиме, читает его содержимое и выводит количество байтов.

Запуск:

```bash
python3 hello.py data/01.log
```

Результат:

```text
Размер файла: 202 байт
```

Результат совпадает с проверкой:

```bash
wc -c data/01.log
```

которая показала:

```text
202 data/01.log
```

## 7. Трассировка hello.py

Для получения трассировки использовалась команда:

```bash
strace -f -o trace.txt python3 hello.py data/01.log
```

Файл трассировки:

```text
trace.txt
```

Всего в трассировке Python было найдено:

```text
413
```

системных вызовов.

Для подсчёта использовалась команда:

```bash
grep -cE '^[0-9]+ +[a-zA-Z_][a-zA-Z0-9_]*\(' trace.txt
```

При работе с `data/01.log` были обнаружены следующие основные системные вызовы:

```text
openat
fstat
lseek
read
read
close
```

Файл открывается вызовом:

```text
openat(AT_FDCWD, "data/01.log", O_RDONLY|O_CLOEXEC) = 3
```

Затем определяется информация о файле:

```text
fstat(3, {st_mode=S_IFREG|0644, st_size=202, ...}) = 0
```

Содержимое файла читается вызовом:

```text
read(3, "auth ERROR Login failed\nauth ERR"..., 203) = 202
```

Таким вызовом были прочитаны все **202 байта** файла.

После этого Python выполняет ещё один вызов:

```text
read(3, "", 1) = 0
```

Он показывает достижение конца файла.

Затем файл закрывается:

```text
close(3) = 0
```

Таким образом, непосредственно содержимое файла было прочитано одним успешным вызовом `read()`, который получил 202 байта. Дополнительный `read()` вернул `0` и использовался для проверки конца файла.

## 8. Трассировка cat

Для сравнения использовалась команда:

```bash
strace -f -o trace_cat.txt cat data/01.log
```

В трассировке `cat` было найдено:

```text
143
```

системных вызова.

Для подсчёта использовалась команда:

```bash
grep -cE '^[0-9]+ +[a-zA-Z_][a-zA-Z0-9_]*\(' trace_cat.txt
```

При обработке файла `cat` выполнил, в частности:

```text
statx(...)
openat(...)
fstat(...)
fstat(...)
splice(...)
pipe(...)
fcntl(...)
splice(...)
splice(...)
```

Файл был открыт:

```text
openat(AT_FDCWD, "data/01.log", O_RDONLY|O_CLOEXEC) = 3
```

Для передачи содержимого использовался `splice()`:

```text
splice(3, NULL, 5, NULL, 1048576, 0) = 202
splice(4, NULL, 1, NULL, 202, 0) = 202
```

Таким образом, `cat` передал 202 байта содержимого файла с помощью `splice()`.

## 9. Сравнение Python и cat

Результаты трассировки:

| Программа                      | Количество системных вызовов |
| ------------------------------ | ---------------------------: |
| `python3 hello.py data/01.log` |                          413 |
| `cat data/01.log`              |                          143 |

Python выполнил на:

```text
413 - 143 = 270
```

системных вызовов больше, чем `cat`.
