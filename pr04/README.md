# Практическая работа №4 — Потоки

## Цель работы

Изучить создание и использование потоков и процессов в Python, сравнить производительность многопоточности и многопроцессности, а также показать различия в использовании общей памяти.

## Среда выполнения

- ОС: Windows 11 + WSL2 / Ubuntu
- Python: 3.x
- Логические процессоры: 12
- Количество потоков/процессов: 4
- Количество повторений каждого измерения: 3
- Для сравнения использовалась медиана трёх измерений.

## 1. Подготовка данных

Файл numbers.txt содержит 10 000 000 целых чисел от 1 до 10 000 000.

## 4. Общая память

Результат memory_demo.py:

Initial: data=0

After thread: Parent: data=100

Process: data=200

After process: Parent: data=100

Потоки используют общее адресное пространство процесса, поэтому изменение видно родителю. Процессы имеют отдельные адресные пространства.

## 5. GIL

GIL ограничивает одновременное выполнение Python-байткода несколькими потоками одного процесса. Поэтому потоки обычно не ускоряют CPU-bound задачи, но хорошо подходят для I/O-bound задач.

## 6. Когда использовать потоки и процессы

Потоки лучше использовать для сетевых операций и других I/O-bound задач. Процессы лучше использовать для CPU-bound задач, когда требуется использовать несколько ядер CPU.

## 7. Контрольные вопросы

1. fork() создаёт дочерний процесс. В родительском процессе он возвращает PID дочернего процесса, а в дочернем — 0. При ошибке возвращается -1.

2. exec() без fork() не создаёт новый процесс, а заменяет программу внутри текущего процесса. PID сохраняется, а код старой программы после успешного exec() не выполняется.

## Итоговый вывод

Практическая работа показала, что потоки особенно полезны для I/O-bound задач, а процессы — для CPU-bound задач. Для вычислительной задачи в данном эксперименте один поток оказался быстрее из-за характера реализации и накладных расходов. Для сетевой задачи четыре потока показали лучшее медианное время.
